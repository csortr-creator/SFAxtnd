# SFAxtnd

Android-клиент на базе **sing-box** для подключения к своим прокси-серверам, работы с подписками и настройки маршрутизации. Форк [sing-box-for-android](https://github.com/SagerNet/sing-box-for-android) с расширенным импортом, поддержкой XHTTP и интерфейсом Material Design 3.

**[Скачать приложение](https://github.com/csortr-creator/SFAxtnd/releases/latest)** · **[Изменения в 1.1.0](RELEASE_NOTES.md)** · **[Все релизы](https://github.com/csortr-creator/SFAxtnd/releases)**

## Возможности

- **Подписки и профили.** Несколько подписок, обновление по расписанию, импорт конфигураций sing-box и ссылок VLESS, VMess, Trojan, Shadowsocks, Hysteria, Hysteria2, TUIC и AnyTLS. Поддерживается преобразование серверов из Clash/Mihomo YAML и JSON, а также Xray JSON. Поддерживаются обычные и Base64-списки ссылок, импорт из буфера обмена, QR-кодов и файлов.
- **XHTTP.** Транспорт для VLESS, VMess и Trojan, включая импорт параметров из ссылок. Поставляемое ядро sing-box 1.14.2 собирается с патчами проекта.
- **Проверка серверов.** Замер задержки до запуска VPN, поиск и сортировка. Результаты сохраняются при переключении подписок; повторные нажатия не ставят тесты в очередь. Можно измерять первый запрос или запрос по прогретому соединению.
- **Маршрутизация.** Прокси, прямое соединение или блокировка для выбранных доменов, суффиксов, IP/CIDR и наборов SRS. Доступны фильтры по сети и протоколу, локальные файлы правил и обновляемые удалённые списки.
- **DNS.** Отдельные серверы для прямого соединения и прокси, резервирование по тайм-ауту, правила DNS, стратегии IPv4/IPv6, кэш, FakeIP и перехват DNS.
- **Оформление.** Светлая, тёмная и системная темы, акцент и размер текста. В уведомлении можно показывать название подписки или текущего сервера.
- **Состояние соединения.** Время работы, скорость загрузки и отдачи, просмотр соединений и журнал событий.

Приложение не предоставляет серверы или подписку: для подключения нужны собственная конфигурация либо данные от вашего провайдера.

## Установка

Опубликованные APK рассчитаны на **Android 7.0 и новее**.

1. Откройте [последний релиз](https://github.com/csortr-creator/SFAxtnd/releases/latest).
2. Скачайте APK для своего устройства.
3. Установите файл. Если Android запросит разрешение, разрешите установку для приложения, через которое открываете APK.

| APK | Для каких устройств |
| --- | --- |
| `arm64-v8a` | Современные устройства с 64-битным ARM-процессором; основной вариант |
| `armeabi-v7a` | Устройства с 32-битным ARM-процессором |
| `universal` | Обе ARM-архитектуры в одном APK; файл большего размера |

Для обновления установите новый APK поверх предыдущей версии. Удалять приложение не нужно.

## Быстрый старт

1. Откройте **Подписки** и нажмите **+**.
2. Для подписки укажите имя, выберите **Удалённый** профиль и вставьте HTTP(S)-адрес подписки. Отдельную ссылку на сервер или файл конфигурации импортируйте через соответствующий пункт импорта.
3. Перейдите в **Серверы** и выберите нужный сервер. Проверить задержку можно до подключения.
4. Нажмите кнопку подключения и подтвердите системный запрос Android на создание VPN-соединения.
5. Дополнительные параметры доступны в **Настройках**. Начать можно с настроек, которые уже содержит подписка.

### Пресеты маршрутизации

**РФ напрямую** — российские домены и IP из двух SRS-наборов направляются без VPN. Это одно правило; оно не сводится к общему суффиксу `.ru`.

**Whitelist для России** — ресурсы из белых списков мобильного интернета направляются напрямую, остальной трафик — через выбранный VPN-сервер. Пресет использует доменные и IP-наборы [hydraponique](https://github.com/hydraponique/roscomvpn-routing). Он предназначен для сетей, где при ограничениях доступен только определённый перечень ресурсов. Сам VPN-сервер тоже должен быть доступен в такой сети.

Удалённые SRS-наборы обновляются по общему интервалу. Для встроенных пресетов есть начальные копии списков, чтобы их можно было использовать до первого скачивания.

### DNS и анализ трафика

В каждой DNS-группе серверы используются по порядку: после ошибки или истечения тайм-аута запрос передаётся следующему. Правила DNS позволяют выбирать прямой или прокси-резолвер либо отклонять запросы для заданных доменов и наборов правил.

**Сниффинг** определяет протокол и, когда это возможно, домен назначения из начальных данных соединения. Это помогает применять доменные правила, когда приложение подключается к IP-адресу. Содержимое зашифрованного соединения он не расшифровывает. Выбор протоколов ограничивает используемые анализаторы.

**Strict route** на Android запрещает приложениям обходить активное VPN-соединение через `allowBypass`. Для запрета соединений при остановленном VPN используется отдельная системная настройка Android «Блокировать соединения без VPN».

### Идентификатор подписки

Для каждого адреса подписки сохраняется отдельный HWID, который повторно передаётся при обновлении. Сервер подписки также получает модель устройства и версию Android в служебных заголовках. Это используется для совместимости с провайдерами, привязывающими подписку к устройству.

## Разработка

Код приложения написан на Kotlin и Jetpack Compose. Ядро — sing-box **1.14.2** с патчами из каталога [patches](patches). Точный процесс сборки и проверки описан в [GitHub Actions](.github/workflows/build.yml).

Для локальной сборки нужны Linux или совместимое окружение, **JDK 17**, Android SDK для `compileSdk`, указанного в [app/build.gradle.kts](app/build.gradle.kts), **NDK 28.2.13676358** и Go, совместимый с `go.mod` ядра. Gradle запускается через wrapper проекта.

В чистом клоне выполните:

```bash
git clone --branch dev https://github.com/csortr-creator/SFAxtnd.git
cd SFAxtnd
git clone --depth 1 --branch v1.14.2 https://github.com/SagerNet/sing-box.git sing-box-core

go install github.com/sagernet/gomobile/cmd/gomobile@v0.1.13
go install github.com/sagernet/gomobile/cmd/gobind@v0.1.13
export PATH="$(go env GOPATH)/bin:$PATH"
# ANDROID_HOME должен указывать на установленный Android SDK.
export ANDROID_NDK_HOME="$ANDROID_HOME/ndk/28.2.13676358"

./patch.sh
(cd sing-box-core && go run ./cmd/internal/build_libbox -target android)
mkdir -p app/libs
cp sing-box-core/libbox.aar app/libs/libbox.aar

./gradlew assembleOtherDebug
```

`patch.sh` следует выполнять один раз в чистом клоне: он меняет и ядро, и исходники приложения. Готовые APK находятся в `app/build/outputs/apk/`. Локальная debug-сборка использует отладочную подпись, если не настроен ключ релиза.

Проверки парсера, маршрутизации и настроек без Android:

```bash
./gradlew -p protocol-tests test
```

CI дополнительно проверяет совместимость XHTTP с Xray, DNS-резервирование и сгенерированные конфигурации ядра перед сборкой APK.

### Проверка импорта подписок

При добавлении и обновлении подписки SFAxtnd проверяет каждую ссылку отдельно, в том числе средствами sing-box. Некорректные и неподдерживаемые серверы не мешают импортировать остальные. После ручного обновления или импорта автоматически открывается **Отчёт импорта** с количеством полученных, импортированных и пропущенных записей, номерами строк и причинами пропусков. Кнопка обновления всех подписок показывает один общий отчёт. Если пригодных серверов нет, обновление не заменяет существующую конфигурацию.

Поддерживаются sing-box JSON, списки ссылок и их Base64-представление: VLESS, VMess, Trojan, Shadowsocks, Hysteria, Hysteria2, TUIC и AnyTLS. Поддерживается преобразование серверов из Clash/Mihomo YAML и JSON, а также Xray JSON. Это не гарантирует совместимость с любой панелью: сервер может требовать другой формат ответа или неподдерживаемые параметры. Проверка конфигурации не подтверждает доступность сервера и успешность авторизации; для этого нужны проверка задержки и подключение.

Из Clash/Mihomo и Xray переносятся параметры поддерживаемых серверов; правила, DNS, группы и системные настройки этих клиентов не переносятся. Отчёт показывает такие ограничения отдельно. Внешние `proxy-providers` нужно добавлять прямыми URL подписок. Неподдерживаемые типы серверов, транспорты и параметры ядра явно отклоняются. HWID передаётся в заголовках запроса подписки; обязательные заголовки и форматы конкретной панели могут отличаться. Универсальная совместимость со всеми панелями не гарантируется.

В ссылках поддерживаются распространённые варианты имён параметров Hysteria и `xmux.maxReuseTimes` для XHTTP. Для `scMaxConcurrentPosts` используется последовательная отправка POST ядром; отличие явно указывается в отчёте. Дополнительное VLESS-шифрование Xray (помимо TLS/Reality) этим ядром не поддерживается.
