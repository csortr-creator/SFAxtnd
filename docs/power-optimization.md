# Фоновая работа и энергопотребление

Изменения в версии 1.1.1:

- Статистика интерфейса поступает только при активном приложении, включённом экране и вне Doze.
- Таймер соединения прекращает обновления в фоне. При возвращении время вычисляется заново по моменту подключения.
- Скорость в уведомлении обновляется раз в три секунды. Количество байтов за интервал пересчитывается в скорость за секунду. Одинаковые заголовок и текст не публикуются повторно.
- Опрос уведомления не запускается при погашенном экране и прекращается в Doze. Настройка динамического уведомления применяется сразу.
- Корутинные задачи уведомления завершаются при остановке службы.
- Подписка на журнал существует только при открытом экране логов. Буфер паузы ограничен 3000 строками.
- Автообновление подписок ожидает подключённую сеть и корректно прерывается при отмене WorkManager.
- Существующая обработка Doze через pause/wake ядра сохранена. Текущее состояние проверяется также после запуска и перезагрузки службы. Выключение экрана само по себе не вызывает pause ядра.

## Проверка на устройстве

1. Запустить VPN при включённом экране: проверить скорость, таймер, смену названия сервера в уведомлении и остановку VPN.
2. Свернуть приложение: уведомление остаётся доступно, таймер и статистика интерфейса не опрашиваются. Вернуться и проверить актуальное время и скорость.
3. Погасить экран, затем включить его: служебный опрос должен прекратиться и возобновиться, VPN не должен останавливаться из-за выключения экрана.
4. На тестовом устройстве проверить Doze через `adb shell dumpsys deviceidle force-idle`; выйти через `adb shell dumpsys deviceidle unforce`. Проверить восстановление соединения и запуск/перезагрузку VPN уже внутри Doze.
5. Открыть журнал, включить паузу и создать много событий: буфер остаётся ограниченным; после снятия паузы нет переполнения. Закрыть журнал и проверить другие экраны.
6. Отключить сеть перед плановым автообновлением подписки: WorkManager должен ожидать сеть вместо неудачных попыток загрузки.

JVM-тесты проверяют условия фонового опроса и подавление повторных публикаций. Android-сборка проверяет совместимость API. Проверки на физическом устройстве и измерения расхода батареи требуют отдельного прогона.

Для сравнения расхода использовать один телефон, одинаковую сеть, сервер, протокол и нагрузку; отдельно сравнивать простой с выключенным экраном и передачу данных. Процент экономии до измерений не заявляется. Удаление комментариев само по себе не уменьшает энергопотребление готового APK.
